Dependency upgrades, rehearsed

Try the
upgrade first.safely.

Sentry builds your project twice, once before and once after one dependency change, then shows exactly what broke and why. Your real project is never touched.

Start How it works

Four steps, no surprises.

01

Copy

Your project is copied into a clean folder. Secrets, build output and links are left behind.

02

Build twice

One side keeps today's version. The other changes only one dependency you named.

03

Compare

Resolved dependencies, test results and the library's public API are diffed. Only what the change caused is reported.

04

Verdict

Accept, reject, or not enough evidence. Every reason points at a file you can open.
